# 코드 읽는 법

이 문서는 "어디서부터 읽어야 하나"에 답한다. 개념별 담당 코드는 [기능 지도](기능_지도.md), 파일별 한 줄 설명은 [모듈 색인](모듈_색인.md)(자동 생성), 테이블 구조는 [스키마](스키마.md), 업무 용어와 순서는 [전체 프로세스와 용어](전체_프로세스와_용어.md)에 있다.

## 1. 한 문단 요약

사고조사보고서(PDF)와 해외 리콜을 받아 위해요인 코드(HF 원인·DT 피해유형)를 붙이고, 품목을 정해 적용되는 KC안전기준을 좁힌 뒤, 관련될 수 있는 **조항·시험방법**을 찾아 담당자가 채택·반려한다. **위반 여부를 판정하지 않는다.** AI는 재료를 차려 두고 사람은 검토한다. 불량(시험으로 아는 것)과 불법(법령으로 아는 것)은 산출물을 갈라 둔다(CLAUDE.md §10).

## 2. 기술 스택

| 층 | 무엇 | 비고 |
| --- | --- | --- |
| 화면·서버 | Next.js 15(App Router), React 19, TypeScript, Tailwind 4 | 서버 컴포넌트가 DB를 직접 조회한다. 서버 액션(`actions.ts`)으로 쓴다 |
| DB | Supabase Postgres + pgvector + pg_cron + pg_net | 접속은 `src/lib/db.ts`의 `getDb()`(postgres.js, `DATABASE_URL`). ORM 없음 — SQL을 직접 쓴다 |
| AI | OpenAI(`openai` 패키지) | 호출 자리는 `src/lib/llm/catalog.ts`의 `CALL_SITES`에 등록(CLAUDE.md §14). 기록은 `llm_call` |
| 배포 | Netlify | 요청 제한 약 30초. 정기 작업은 DB의 pg_cron이 `/api/jobs/*`를 부른다 |
| 테스트 | 자동 테스트 없음 | 검증은 `tsc`·`eslint`·`build`·실제 화면·DB 실측. 평가 스크립트는 `scripts/eval*.ts` |

## 3. 디렉터리

```
src/app/            화면과 API (아래 4장)
src/components/     화면 부품. 업무 로직 없음
src/lib/            업무 로직 전부 — 화면·스크립트가 함께 쓴다 (CLAUDE.md §9)
  cases/              사건(사고·리콜) 처리: PDF 추출, 품목 판정(resolve-scope), 분류됨 정의(classified)
  gpc/                품목분류(GPC) 부여·검증·국내 갈래 되짚기
  standards/          안전기준 적재·동기화·조항 코드 부여
  search/             조항 검색(하이브리드·RRF·HyDE·재채점)
  second-opinion/     병행 점검 — 보고서 결론을 그대로 믿지 않는 계층 (CLAUDE.md §13)
  recall/             해외 리콜 수집·근거 표준 대조
  llm/                OpenAI 호출 한 자리, 태깅, 비용 기록
  policy/             정책 현황판 집계
  taxonomy/ terms/    법정 품목표·품목 사전
  codebook/           위해요인 코드북 조회
scripts/            명령줄 진입점 (npm run …). 얇게 두고 로직은 src/lib 에 둔다
supabase/migrations/ 본 체계 스키마 (번호순, 이미 적용된 것은 고치지 않는다)
codebook/           코드북 SQL·적재 스크립트
docs/               설계·개념·운영 문서. docs/wiki 는 업무 개념, docs/raw 는 원자료
site/               GitHub Pages 소개페이지 (정적)
구현이력.md          라운드별 기록 — 왜 그렇게 정했는지의 원본
```

## 4. 화면(`src/app`)과 업무 역할

| 경로 | 누가 | 하는 일 |
| --- | --- | --- |
| `/` | 모두 | 역할별 입구(카드) |
| `/accidents`, `/accidents/confirm/[fileId]` | 사고조사 담당자 | 올리기, 원본과 나란히 원문 확인 |
| `/recalls` (`?stage=link`) | 리콜 분석자 | 1단계 국내 관련성(국내 유통·품목), 2단계 조항 연계 |
| `/analysis/[caseId]` | 사고조사·리콜 | 사건 검토 한 화면 — 조항 채택·반려, 병행 점검, 참고 |
| `/standards`, `/standards/review` | KC기준 담당자 | 기준 원문, 조항 위해요인 코드 검수 |
| `/dictionary` (`?tab=keyword\|link\|term`) | KC기준·리콜 | 품목 판정 사전 |
| `/policy` | 정책담당자 | 위해 분포·불량/불법·사각지대 후보 (내부 전용) |
| `/admin` (`?tab=jobs\|llm\|progress`) | 관리자 | 상태·알림, 자동 작업, AI 비용, 진척 |
| `/codebook` | 모두 | 코드 목록 (읽기 전용) |
| `/api/jobs/[job]` | DB(pg_cron) | 정기 작업 진입점. `JOBS_TOKEN` 으로 지킨다 |

옛 주소(`/ops`, `/llm`, `/insights`, `/keywords`, `/terms`, `/accidents/status`, `/recalls/status`, `/analysis/*/insight`)는 `redirect()` 로 새 자리에 넘겨준다. 화면 폴더 안의 관례: `page.tsx`(화면), `data.ts`(조회 — 여러 화면이 공유), `actions.ts`(서버 액션), `loading.tsx`(스켈레톤).

## 5. 데이터가 흐르는 길

```
[기준]  KC안전기준/ 폴더 → standards:sync → standard · clause
         → 위해요인 코드 부여(AI) → clause_tag → 사람이 검수(/standards/review)
         → 임베딩(pg_cron 1분) → 의미 검색 준비
[사건]  사고 PDF 업로드 → 글자·개인정보 검사 → 사람이 원문 확인 → case_event
        해외 리콜 → 2분마다 3건씩 수집(recall/load.ts) → case_event + case_tag
         → 품목 판정(cases/resolve-scope.ts) → scope_evidence
[분석]  standardsForCase(사건) → 적용 기준 세트 → 조항 검색(search/run.ts)
         → match_run · match_result → 사람이 채택·반려 → review_log
        (사고만) 병행 점검(second-opinion/run.ts) → second_opinion_finding
[통계]  case_tag · second_opinion_finding · insight 뷰 → /policy
```

두 가지가 헷갈리기 쉽다. (1) **품목 판정**은 "어느 기준 세트를 볼 것인가"를 정하고, **조항 검색**은 그 세트 안에서 조항을 찾는다 — 하이브리드·HyDE는 품목이 정해진 뒤에만 쓴다. (2) 「품목이 정해졌다」는 칸 하나로 세지 않는다 — `src/lib/cases/classified.ts` 한 곳이 정의다.

## 6. 어디서부터 읽을까

1. 무엇을 만들거나 고치려면 **먼저** [기능 지도](기능_지도.md)에서 그 개념의 담당 코드를 찾는다(CLAUDE.md §16).
2. 그 `src/lib/<도메인>/` 파일의 머리 주석을 읽는다 — 「왜 만들었나」「무엇을 하지 않나」가 적혀 있고, 원칙 대부분이 거기 있다.
3. 화면 쪽은 `src/app/<경로>/page.tsx` → 같은 폴더의 `data.ts` → `actions.ts` 순서로 읽는다.
4. 이 일이 왜 이렇게 됐는지는 `구현이력.md`(맨 위가 최신, 4,000줄 넘음 — 키워드로 찾는다)에 있다.
5. 파일을 찾을 때는 [모듈 색인](모듈_색인.md)을 훑는다.

## 7. 명령

| 하려는 일 | 명령 |
| --- | --- |
| 개발 서버 | `npm run dev` |
| 타입·린트·빌드 | `npm run typecheck` · `npm run lint` · `npm run build` |
| DB 읽기 전용 조회 | `npm run db:query -- "select …"` |
| 마이그레이션 적용 | `npm run db:push` (`-- --dry` 로 미리 보기) |
| 모듈 색인 다시 만들기 | `npm run docs:index` (낡았는지만 보려면 `-- --check`) |
| 클라이언트 번들에 비밀값이 새는지 | `npm run check:bundle` (build 뒤) |

환경변수는 `.env.local`(커밋 금지), 항목 목록은 `.env.example`. `DATABASE_URL` 과 `OPENAI_API_KEY` 가 없으면 조회·AI 호출이 모두 막힌다. 화면은 `SITE_AUTH_PASSWORD` 가 설정되면 기본 인증이 걸린다.

## 8. 자주 빠지는 함정 (실제로 겪은 것)

- **같은 개념을 담은 칸이 여럿이다.** 리콜 품목은 등록 품목(`product_scope_id`, 40건)·자동 판정(`scope_evidence`, 2,081건)·원본 GPC(1,939건)가 따로다. 칸 하나만 보고 "비었다"고 판단하지 않는다(CLAUDE.md §16).
- **코드가 있다고 데이터가 차 있는 것은 아니다.** GPC 판정 코드는 있지만 안전기준 76종 중 5건만 돌았다. 설계 전에 `db:query` 로 잰다.
- **마이그레이션 해시는 줄바꿈 차이로 달라질 수 있다.** Windows(CRLF)와 다른 환경(LF)이 섞여 옛 파일이 다시 실행된 일이 있다 — `db-push.ts` 가 줄바꿈을 맞춰 비교한다. 적용된 마이그레이션은 고치지 않는다.
- **정기 작업은 DB에서 돈다.** 웹사이트가 꺼져 있어도 pg_cron이 돈다. 알림도 DB 함수(`ops_watch`)가 보낸다(`023`·`068`·`071`).
- **새 DB 함수는 `anon`/`authenticated` 실행 권한이 자동으로 열린다.** 의도한 것이 아니면 `revoke` 한다(CLAUDE.md §8).
- **Windows 에서 종료 도구가 서버를 못 끌 때가 있다.** 띄운 개발 서버는 `netstat` 으로 포트가 풀렸는지 확인한다(CLAUDE.md §14).
- **파일 인코딩은 UTF-8, 문서의 문단은 한 줄**(CLAUDE.md §5). 큰 문서(`구현이력.md`)는 `Write` 로 통째로 덮지 말고 `Edit` 로 맨 위에만 끼운다.
