# 색인 (docs/wiki/)

`docs/raw/` 아래 업무자료가 어디 있는지와, `docs/wiki/개념/` 아래 어느 개념
문서가 그것을 사람이 읽기 좋게 정리해 뒀는지를 한 곳에서 찾는 표다.
`.claude/skills/kc-work-reference/references/업무자료-지도.md`를 대체한다
(원자료 위치·행수 안내 + 개념 문서 라우팅 힌트를 여기 하나로 합침).

새 원자료가 `docs/raw/`에 추가되면 이 파일에 한 줄을 추가한다 — 파일 위치,
무엇이 들어 있는지, 몇 행/몇 종인지. 새로운 주제/워크플로면 개념 문서도
새로 쓴다(판단 기준은 `.claude/skills/kc-work-reference/SKILL.md`의
"위키 갱신" 절 참고).

**커버리지 표시.** 각 원자료 항목에 아래 세 표시 중 하나를 붙인다 —
"이 파일이 정리됐는지"를 색인만 보고 알 수 있게 하기 위해서다(라운드
64에서 `★★★★업무이해 20230405.xlsx`가 여러 문서에 인용되면서도 정작
개념 문서가 없다는 것을 뒤늦게 발견한 뒤 정한 규칙).

- (표시 없음) — 개념 문서가 이 파일 내용을 충분히 다룬다.
- **부분** — 개념 문서가 이 파일의 일부만 옮겼다(예: "요지만").
- **미다이제스트** — 아직 어떤 개념 문서도 이 파일을 다루지 않는다.
  질문이 이 파일과 관련되면 원자료를 직접 열어 확인하고, 확인한 내용이
  재사용할 만하면 개념 문서를 새로 쓴다.

## 요약 문서에는 출처를 반드시 남긴다 (담당자 지시, 2026-09-09)

원자료(고시·설명회 자료·엑셀)를 `docs/wiki/개념/*.md`로 옮겨 정리할 때는
**문서 머리에 출처를 적는다.** 고시면 고시 번호와 행정규칙일련번호, 설명회
자료면 발표 기관·날짜, 실측이면 무엇을 세었고 언제 쟀는지다.

이유는 두 가지다. 요약은 원문이 아니므로 다툼이 생기면 원문으로 되짚어야
하고, 숫자는 검수가 진행되면 달라지므로 잰 날짜가 없으면 옛 숫자인지 알 수
없다.

**담당자 판단으로 정한 것은 그 사실과 우리 관찰을 함께 적는다.** 판단을
따르되 관찰을 지우지 않는다 — 나중에 의심할 일이 생기면 되짚을 수 있어야
한다(예: `docs/wiki/개념/GPC/표준제품분류체계_K-GPC.md` §5의 품목분류 코드
출처).

기존 개념과 이어지는 사소한 원자료 추가는 이 색인 한 줄 + 해당 개념 문서의
출처표만 갱신하고, 완전히 새로운 주제/워크플로는 새 개념 문서를 쓴다.
`분석/`처럼 날짜별 스냅샷 원자료는 이 색인에 한 줄만 추가한다.
