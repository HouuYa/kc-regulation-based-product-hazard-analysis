# 제도해석·업무자료 조회

법령·제도·업무자료의 뜻을 추측하지 않는다. 담당자가 정리해 둔 원자료가
`docs/`에 있다. 원자료에 없으면 "원자료에 없음"이라고 답하고 지어내지
않는다(CLAUDE.md §10).

## STEP 1 — 위키 확인 및 최신화 (매번 필수)

`docs/`는 두 갈래다 — `docs/raw/`는 원자료(PDF·xlsx·JSON 등), `docs/wiki/`는
그 원자료를 사람이 읽기 좋게 정리한 개념 문서다. 담당자가 수시로 원자료를
넣거나 폴더명을 바꾼다(예: `docs/GPC 용어/` → `docs/용어/` → 지금의
`docs/raw/용어/`로 두 번 정리된 사례). 그래서 위키 내용을 무조건 믿지 않고,
스킬을 쓸 때마다 아래 순서를 따른다.

1. `docs/wiki/색인.md`를 먼저 연다 — 질문과 관련된 개념 문서가 있는지,
   있다면 어느 클러스터(GPC·법령제도·해외리콜연동·검증평가)인지 찾는다.
2. 개념 문서가 있으면 그 문서를 읽는다. 문서 머리의 `updated:` 날짜가
   최근 `docs/raw/`쪽 변화보다 뚜렷이 오래됐거나, 문서가 인용하는 파일이
   실제로 없어졌으면(예: `docs/raw/` 아래를 가볍게 훑어 대조) 그 사실을
   밝히고 원자료를 직접 본다.
3. 위키가 그 질문을 다루지 않으면 `docs/wiki/색인.md`의 "원자료" 절에서
   해당 `docs/raw/...` 파일을 찾아 직접 읽는다.
4. 색인 자체가 실물과 어긋나 있으면(지도에 없는 파일·폴더, 사라진 파일 등)
   답하기 전에 먼저 갱신한다(아래 "위키 갱신" 참고).

## STEP 2 — 불법 vs 불량 판정 (품목/사고 관련 질문)

이 체계의 산출물이 갈리는 지점이다. 반드시 구분한다.

| | 불량 | 불법 |
|---|---|---|
| 무엇 | 안전기준의 기능·성능에 불합격 | 법령이 정한 의무 위반(인증·표시·부품변경 재인증 등) |
| 확인 | 시험을 해야 안다 | 법령을 보면 판정된다 |
| 산출물 | 시험항목 | 인증·표시 확인항목 |

세부 표시사항이 KC안전기준 문서 안에 있더라도, 그것을 지키지 않은 것은 표시
의무 위반이므로 **불법**이다. 시험항목으로 답하지 않는다. 조항 쪽은
`clause.clause_role`이 `REQUIREMENT`(불량 쪽 요건)와 `MARKING`(불법 쪽 표시
의무)으로 이미 나뉘어 있으니 대조한다.

**판정 순서**

1. 품목/사고 서술이 법정 품목인지 `docs/raw/제품안전법제도/안전기준목록조사
   취합(전기 생활 어린이).xlsx`(품목→기준 558행)로 확인한다.
2. 인증·표시·부품변경 위반 여부는 `docs/raw/제품안전법제도/★★★★업무이해
   20230405.xlsx`의 「불법제품 단속」(505행)에서 조치 유형과 사유 조문을
   찾는다.
3. 리콜 이행·과태료 관련 질문이면 같은 파일의 「리콜이행 점검」(127행)을
   본다.
4. 근거(행 번호 또는 조문)를 인용하고, 불량/불법 어느 쪽인지 위 표로 구분해
   답한다. 두 원자료 어디에도 없으면 "원자료에 없음"이라고 밝힌다 —
   그럴듯하게 추측하지 않는다.

## STEP 3 — 원자료 읽는 법

- xlsx는 라이브러리를 새로 들이지 않고 zip + XML 직접 파싱으로 읽는다
  (`scripts/build-answer-key.ts` 방식 재사용).
- PDF는 Read 도구로 직접 읽는다.
- 큰 파일을 반복 조회할 때는 매번 전체를 파싱하지 말고, 이미 이 세션에서
  파싱한 결과가 있으면 재사용한다.

## STEP 4 — 답변 형식

- 근거를 먼저 밝힌다: 파일명 + 행 번호/조문.
- 불법/불량이 갈리는 질문이면 표 또는 명확한 한 문장으로 구분해 제시한다.
- 원자료에 없는 내용은 "원자료에 없음. 추가로 확인이 필요하다"라고 명시한다.
- 코드 변경으로 이어지는 질문(매핑 로직, `clause_role` 판정 등)이면 관련
  코드 위치도 함께 짚는다.
- 위키 개념 문서로 답했으면 그 문서가 인용한 `docs/raw/...` 원자료도 함께
  밝힌다 — 위키는 요약이지 원문이 아니므로, 다툼이 생기면 원문으로
  되짚을 수 있어야 한다.

## 위키 갱신

`docs/raw/`에 새 업무자료가 추가되면(엑셀·PDF·JSON 등) 아래 기준으로
`docs/wiki/색인.md`와 개념 문서를 갱신한다.

- **기존 개념과 이어지는 사소한 원자료 추가**(예: 같은 주제의 고시 개정판
  하나 더) → 해당 개념 문서의 "이 문서의 출처" 절에 한 줄 보태고,
  `docs/wiki/색인.md`에도 한 줄 추가한다. 새 문서는 만들지 않는다.
- **완전히 새로운 주제·워크플로**(지금까지 개념 문서가 없던 영역) → 새
  개념 문서를 `docs/wiki/개념/<클러스터>/`에 쓰고 `색인.md`에 추가한다.
  형식은 기존 개념 문서(예: `개념/GPC/표준제품분류체계_K-GPC.md`)의 "0.
  이 문서의 출처" 절 + §11 표준 frontmatter(+ `sources: []`)를 따른다.
- **날짜별 스냅샷 원자료**(`docs/raw/분석/` 같은 실측 대조 결과) → `색인.md`에
  새 폴더 한 줄만 추가한다. "읽는 법" 개념 문서는 측정 방법론 자체가
  바뀌었을 때만 고친다.
- 라운드 로그(`round-log` 스킬)에 "업무자료 추가"가 언급되면 `색인.md`가
  함께 갱신됐는지 확인한다.
- CLAUDE.md §11의 frontmatter 규칙과 위키 전용 `sources: []` 필드는
  CLAUDE.md §10·§11을 참고한다.
- **커버리지 표시를 유지한다.** `색인.md`는 원자료 항목마다 (표시 없음=
  충분히 다뤄짐) / **부분** / **미다이제스트** 중 하나를 붙인다(라운드
  64에서 `★★★★업무이해 20230405.xlsx`가 여러 곳에 인용되면서도 개념
  문서가 없다는 것을 뒤늦게 발견한 뒤 정한 규칙 — CLAUDE.md·SKILL.md가
  어떤 원자료를 근거로 인용한다고 해서 그 자체로 "다이제스트됨"은 아니다).
  이 스킬로 원자료를 실제로 열어 답한 뒤에는, 그 파일이 아직
  **미다이제스트**로 표시돼 있는지 확인하고 표시를 갱신한다 — 개념
  문서를 새로 썼으면 표시를 지우고, 일부만 참고했으면 **부분**으로
  낮춘다.
