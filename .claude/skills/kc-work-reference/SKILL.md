# 제도해석·업무자료 조회

법령·제도·업무자료의 뜻을 추측하지 않는다. 담당자가 정리해 둔 원자료가
`docs/`에 있다. 원자료에 없으면 "원자료에 없음"이라고 답하고 지어내지
않는다(CLAUDE.md §10).

## STEP 1 — 업무자료 지도 확인 및 최신화 (매번 필수)

`docs/`는 담당자가 수시로 파일을 넣거나 폴더명을 바꾼다(예: `docs/GPC 용어/`
→ `docs/용어/`로 정리된 사례). 그래서 지도 내용을 무조건 믿지 않고, 스킬을
쓸 때마다 아래를 먼저 한다.

1. `docs/`(및 관련 하위 폴더)를 가볍게 훑는다 — 폴더 목록 정도의 얕은
   확인이면 충분하고, 매번 전체 파일을 다시 읽을 필요는 없다.
2. 그 결과를 `references/업무자료-지도.md`와 대조한다. 지도에 없는
   파일·폴더가 있거나, 지도에 있는 파일·폴더가 이름이 바뀌었거나 사라졌으면
   답하기 전에 지도를 먼저 갱신한다(아래 "지도 갱신" 참고).
3. 지도가 최신 상태임을 확인한 뒤에만 그 안에서 질문과 관련된 파일을
   찾는다.

## STEP 2 — 불법 vs 불량 판정 (품목/사고 관련 질문)

이 체계의 산출물이 갈리는 지점이다. 반드시 구분한다.

| | 불량 | 불법 |
|---|---|---|
| 무엇 | 안전기준의 기능·성능에 불합격 | 법령이 정한 의무 위반(인증·표시·부품변경 재인증 등) |
| 확인 | 시험을 해야 안다 | 법령을 보면 판정된다 |
| 산출물 | 시험항목 | 인증·표시 확인항목 |

세부 표시사항이 KC안전기준 문서 안에 있더라도, 그것을 지키지 않은 것은 표시
의무 위반이므로 **불법**이다. 시험항목으로 답하지 않는다. 조항 쪽은
`clause.clause_role`이 `REQUIREMENT`(불량 쪽 요건)와 `MARKING`(불법 쪽 표시
의무)으로 이미 나뉘어 있으니 대조한다.

**판정 순서**

1. 품목/사고 서술이 법정 품목인지 `안전기준목록조사 취합(전기 생활
   어린이).xlsx`(품목→기준 558행)로 확인한다.
2. 인증·표시·부품변경 위반 여부는 `★★★★업무이해 20230405.xlsx`의 「불법제품
   단속」(505행)에서 조치 유형과 사유 조문을 찾는다.
3. 리콜 이행·과태료 관련 질문이면 같은 파일의 「리콜이행 점검」(127행)을
   본다.
4. 근거(행 번호 또는 조문)를 인용하고, 불량/불법 어느 쪽인지 위 표로 구분해
   답한다. 두 원자료 어디에도 없으면 "원자료에 없음"이라고 밝힌다 —
   그럴듯하게 추측하지 않는다.

## STEP 3 — 원자료 읽는 법

- xlsx는 라이브러리를 새로 들이지 않고 zip + XML 직접 파싱으로 읽는다
  (`scripts/build-answer-key.ts` 방식 재사용).
- PDF는 Read 도구로 직접 읽는다.
- 큰 파일을 반복 조회할 때는 매번 전체를 파싱하지 말고, 이미 이 세션에서
  파싱한 결과가 있으면 재사용한다.

## STEP 4 — 답변 형식

- 근거를 먼저 밝힌다: 파일명 + 행 번호/조문.
- 불법/불량이 갈리는 질문이면 표 또는 명확한 한 문장으로 구분해 제시한다.
- 원자료에 없는 내용은 "원자료에 없음. 추가로 확인이 필요하다"라고 명시한다.
- 코드 변경으로 이어지는 질문(매핑 로직, `clause_role` 판정 등)이면 관련
  코드 위치도 함께 짚는다.

## 지도 갱신

`docs/`에 새 업무자료가 추가되면(엑셀·PDF·JSON 등) `references/업무자료-지도.md`에
한 줄 추가한다 — 파일 위치, 무엇이 들어 있는지, 몇 행/몇 종인지. 라운드
로그(`round-log` 스킬)에 "업무자료 추가"가 언급되면 이 지도도 함께 갱신했는지
확인한다.
