---

## 4대 철칙 (절대 준수)

1. **의미 불변** — 사실·주장·수치·고유명사·직접 인용은 100% 원문 보존
2. **근거 기반** — 탐지된 span에만 수술적 수정. 탐지 근거 없는 구간은 건드리지 않음
3. **장르 유지** — 보고서를 에세이로, 공문을 블로그로 옮기지 않음
4. **과윤문 금지** — 변경률 30% 초과 시 경고 포함 / 50% 초과 시 강제 중단 후 사용자 확인

**Do-NOT List (탐지·윤문 대상 제외)**
- 수치·단위·날짜, 고유명사·인명·기관명·제품명·모델명
- 큰따옴표 내부 직접 인용
- 법률·규정 조문 (예: 「제품안전기본법」 제○조)
- 학술 개념어·전문 용어 (불가피한 경우)
- 영어 약어 (AI, KC, IEC, ISO 등 — B카테고리 과도 병기만 탐지)

## STEP 0 — 사용자 intake

**텍스트가 함께 제공된 경우**: STEP 1로 직행. 장르·강도는 텍스트에서 자동 추론.

**텍스트 없이 트리거된 경우**: 아래를 물어본다.
```
어떤 글을 윤문할까요? 아래 정보를 함께 주시면 더 정밀하게 처리합니다.

1. 윤문할 텍스트 (붙여넣기)
2. 장르 (하나 선택): 정부보고서 / 정책문서 / 공문 / 기획서 / 블로그 / 칼럼 / SNS / 기타
3. 교정 강도 (기본: 표준): 보수적(S1만) / 표준(S1+S2) / 적극적(S1+S2+S3)
```

## STEP 1 — 참조 파일 로드 및 탐지

**참조 파일 로드 규칙:**

| 파일 | 로드 조건 |
|------|-----------|
| `references/quick-rules.md` | 항상 로드 (STEP 1 시작 전) |
| `references/gov-patterns.md` | 장르가 정부보고서·정책문서·공문·기획서인 경우 또는 텍스트에서 행정 문체 감지 시 |
| `references/taxonomy-compact.md` | Strict 모드 전환 시에만 추가 로드 |
| `references/project-terms.md` | KC안전기준 프로젝트의 화면·설계문서·알림을 윤문할 때 |
| `references/project-preservation.md` | KC안전기준 프로젝트의 파일을 윤문할 때 |

**탐지 작업:**
- `quick-rules.md`의 S1/S2 패턴을 기준으로 텍스트 스캔
- 정부 문서 해당 시 `gov-patterns.md`의 K 카테고리 추가 스캔
- 탐지 결과: 각 패턴에 대해 `[위치|카테고리|심각도|원문 span|처방]` 내부 목록 생성

프로젝트 파일을 윤문할 때는 일반 규칙보다 먼저 프로젝트 보존 규칙을 적용한다. 화면 문구는 UI 모드, 운영 알림은 운영알림 모드, README는 안내문 모드, 00·01 설계문서와 `구현이력.md`는 설계문서 모드로 판정한다. 법령·안전기준 원문과 직접 인용은 윤문 대상에서 제외한다.

## STEP 2 — 윤문

- 탐지 목록 기준으로 span 단위 수술적 교정
- 교정 시마다 의미 동등성 자체 확인
- 변경 글자 수 추적 → 변경률 = 변경 글자 수 / 전체 글자 수 × 100
- 변경률 > 30%: 윤문본에 `[경고: 변경률 XX%]` 표시
- 변경률 > 50%: 윤문 중단 → 사용자에게 확인 요청
- `project-preservation.md`의 보호 토큰, 책임 주체, 상태 의미를 바꾼 경우 윤문을 중단하고 확인 요청

## STEP 4 — 자체검증 6항

윤문본을 quick-rules.md 기준으로 재점검:

| 항 | 검증 내용 | 합격 기준 |
|----|-----------|-----------|
| V1 | S1 패턴 잔존 건수 | 0건 |
| V2 | 의미 동등성 | 주요 주장·수치·고유명사 100% 보존 |
| V3 | 과윤문 여부 | 변경률 < 50% |
| V4 | 장르 일관성 | 문체 유지 |
| V5 | S2 잔존 건수 | ≤ 3건 (표준 강도 기준) |
| V6 | K 패턴 잔존 건수 (정부문서) | ≤ 1건 |

프로젝트 파일에는 다음 보존 검사를 추가한다.

| 항 | 검증 내용 | 합격 기준 |
|---|---|---|
| P1 | 보호 토큰·수치·코드·URL | 값 변경 0건 |
| P2 | 책임 주체·판단 강도 | 의미 강화·약화 0건 |
| P3 | 상태값·버튼 동작 | 실제 기능과 불일치 0건 |
| P4 | 표준 용어 | `project-terms.md`와 불일치 0건 |

자동 검사는 동일성 후보를 찾는 보조 수단이다. 통과해도 법령·설계 의미와 화면 동작은 사람이 확인한다.

**등급 판정:**
- **A**: V1~V6 전항 합격, 개선률 70%+
- **B**: V1·V2·V3 합격, V5 ≤ 4건
- **C**: S1 1~2건 잔존 또는 과윤문 시그널 → 재윤문 제안
- **D**: S1 3건+ 또는 변경률 50%+ → 사용자 검토 권고

## STEP 5 — 출력 (기본: Markdown)

**기본 출력은 항상 Markdown**. Canvas(JSX)는 사용자가 명시적으로 요청(`--canvas` / "Canvas로 보여줘")한 경우에만 생성.

### Markdown 출력 형식

아래 구조를 대화창에 직접 출력한다.

```
## 윤문 결과 — [문서명]

> 등급 **X** | 변경률 X.X% | S1 X→0건 | S2 X→X건
> 프로젝트 보존 검사: 통과/확인 필요 | 책임 주체 보존: 통과/확인 필요

---

### 변경 내역 (총 N건)

**[1] [위치 설명]**
- 원문: `...원문 span...`
- 윤문: `...교정 span...`
> `[카테고리코드 심각도]` **탐지 패턴명** — 교정 이유 한 줄

**[2] ...**
...

프로젝트 파일 윤문 결과에는 다음을 추가한다.

### 보존 항목 확인

- 수치·단위·날짜:
- 코드·상태값·조항번호:
- URL·명령어·환경변수:
- 법령·직접 인용:
- 책임 주체·판단 강도:

---

### 최종 윤문본

(전체 윤문 텍스트)
```

### 출력 규칙

- **변경 내역**: 변경된 span만 발췌. 전체 문장 중 바뀐 부분만 표시 (문맥 포함 1줄).
- **원문/윤문 표시**: 인라인 코드(backtick)로 감싸 구별.
- **이유**: `[코드 심각도]` 태그 + 패턴명 + 이유 한 줄. 간결하게.
- **변경 없는 구간**: 나열하지 않음 (변경 내역에 미포함).
- **최종 윤문본**: 변경 내역 다음에 전체 윤문 텍스트를 코드블록 없이 그대로 출력.

### Canvas(JSX) 출력 — 명시적 요청 시에만

사용자가 `--canvas` 또는 "Canvas로 보여줘"라고 요청한 경우:
1. `create_file`로 `/mnt/user-data/outputs/humanize-result.jsx` 생성
2. `present_files`로 공유
3. 포함 요소: 원문/윤문 탭, 패턴 바 차트, 등급 배지, 복사 버튼, 편집 영역

## Strict 모드 추가 단계

Fast 모드의 STEP 1~5에 더해:

**S-STEP 1**: `taxonomy-compact.md` 로드 → 60+ 전체 패턴으로 재탐지
**S-STEP 2**: 탐지 결과와 Fast 탐지 결과 병합, 우선순위 정렬
**S-STEP 3**: 2차 윤문 (S3 패턴 포함)
**S-STEP 4**: 자체검증 강화 (모든 카테고리 잔존 0~1건 목표)

## 재윤문 요청 처리

```
"이 카테고리만 다시"  → Strict 모드로 해당 카테고리만 재처리
"번역투만 더 손봐줘"  → A 카테고리 재처리
"행정 문체만 고쳐줘"  → K 카테고리 재처리
"강도 낮춰줘"         → 보수적 강도(S1만)로 재처리
"원문 톤 더 살려줘"   → 변경률 상한 15%로 재처리
"2차 윤문해줘"        → 현재 윤문본을 입력으로 재처리
```
