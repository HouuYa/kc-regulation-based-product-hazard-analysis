# KC안전기준 프로젝트 용어 사전

이 사전은 문장을 쉽게 고칠 때도 업무 의미를 바꾸지 않도록 보호할 기준이다.

## 화면 권장 표현

| 내부·어려운 표현 | 화면 권장 표현 | 사용 설명 |
|---|---|---|
| 태깅 | 위해요인 코드 부여 | 원인(HF)·피해유형(DT) 코드를 붙이는 일 |
| 임베딩 | 의미 검색 준비 | 문장을 뜻으로 찾을 수 있게 준비하는 일 |
| 시험연결 | 시험방법 연결 | 요건과 확인 시험을 잇는 관계 |
| 시험조건 | 시험 항목·허용치 | 시험에서 확인할 수치와 기준 |
| 배치 | 자동 작업 | 정해진 시간에 반복 실행되는 작업 |
| 확정됨 | 원문 확인함 | 담당자가 추출 원문을 확인한 상태 |
| 미해결 참조 | 다른 기준을 가리키는 참조 | 연결 대상이 다른 기준에 있는 상태 |
| 사건 | 사고보고서 또는 리콜 | 화면에서는 출처를 구체적으로 표시 |
| 재채점 | 후보 순서 다시 확인 | 검색 후보의 순서를 다시 검토하는 일 |
| 기준 개선 | 기준 개선 검토 신호 | 자동으로 개정 필요성을 확정하지 않음 |

## 반드시 보존할 표현

다음은 문체가 어색해도 임의로 바꾸지 않는다.

- `HF`, `DT`, `GPC`, `RRF`, `KC`, `IEC`, `ISO`
- 코드값: `HF.*`, `DT.*`, `SCOPE_UNRESOLVED`, `TAGGING_INCOMPLETE` 등
- 안전기준 조항번호, 시험방법 번호, 허용치, 단위, 날짜, 건수
- `auto_unreviewed`, `approved`, `rejected` 등 검수 상태값
- `case_event`, `match_result`, `review_log` 등 테이블·컬럼명
- `npm run ...`, API 경로, URL, 모델명, 환경변수명
- 「제품안전기본법」 등 법령명과 직접 인용문

## 바꾸면 안 되는 의미

- 담당자가 판단하는 일을 시스템이 판단하는 것으로 바꾸지 않는다.
- “관련될 수 있음”을 “관련 있음” 또는 “위반”으로 강화하지 않는다.
- “확인 필요”를 “오류” 또는 “완료”로 바꾸지 않는다.
- “자료 부족”·“비교 불가”·“미검토”를 정상 결과로 바꾸지 않는다.
- 사고·리콜·안전기준의 출처를 서로 바꾸지 않는다.
