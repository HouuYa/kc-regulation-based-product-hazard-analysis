# 프로젝트 문구 보존 검사

## 적용 대상

| 대상 | 처리 방식 |
|---|---|
| 관리자 화면·버튼·상태 | 짧고 행동 중심으로 수정 |
| 운영 알림 | 오류 코드·작업명·수치를 보존하며 간결화 |
| README·사용 안내 | 설명을 쉽게 바꿀 수 있으나 제한사항 보존 |
| 00·01 설계문서 | 설계 결정·대안·근거·미확정 사항을 보존하며 보수적으로 수정 |
| 법령·안전기준 원문 | 윤문하지 않고 인용 그대로 유지 |
| `구현이력.md` | 실측값·결정 이유·사고 경위를 보존하며 수정 |

## 보존 토큰 검사

윤문 전후 다음 항목의 개수와 값을 비교한다.

- 숫자·단위·날짜
- 코드·상태값·조항번호
- URL·API 경로·환경변수명·명령어
- 모델명·기관명·제품명·테이블명
- 법령명과 직접 인용

하나라도 달라지면 자동 합격시키지 않고 `확인 필요`로 표시한다. 숫자 표기의 쉼표나 공백처럼 표현만 달라진 경우에도 사람이 확인한다.

## 책임과 판단 주체 검사

- `담당자`, `전문가`, `시스템`, `AI`, `자동 작업`의 주체를 전후로 비교한다.
- 시스템이 제안·표시·기록하는 일을 시스템이 확정·판정하는 말로 바꾸지 않는다.
- “검토 신호”를 “개선 필요”로 확정하지 않는다.
- “후보”를 “정답”으로 바꾸지 않는다.

## UI 문구 검사

- 버튼은 명사보다 동사 중심으로 쓴다.
- 상태 문구는 `현재 상태 → 영향 → 다음 행동` 순으로 짧게 쓴다.
- 화살표 흐름은 4~5단계를 넘기지 않는다.
- 링크처럼 보이는 문구는 실제 이동·작업 대상과 일치해야 한다.
- 같은 상태는 `src/lib/terms.ts`의 표현과 맞춘다.
